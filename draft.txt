Identify the background/motivation
Perkembangan pesat aplikasi IoT (Internet of Things) mendorong kebutuhan akan komputasi real-time dengan latensi sangat rendah. Namun, perangkat IoT memiliki keterbatasan mendasar: ukuran fisik kecil, baterai terbatas, dan kemampuan komputasi yang lemah — sehingga tidak mampu memproses data intensif secara lokal dalam waktu singkat.
Mobile-Edge Computing (MEC) hadir sebagai solusi dengan memindahkan (offloading) task komputasi dari perangkat pengguna ke server yang berada di tepi jaringan (network edge), bukan ke cloud terpusat yang jauh. Keunggulannya dibanding cloud konvensional:
Latensi lebih rendah (server fisik lebih dekat) 
Koneksi wireless lebih stabil 
Layanan komputasi dan komunikasi lebih fleksibel
Sebagian besar literatur sebelumnya mengasumsikan kapasitas komputasi edge cloud tidak terbatas (infinite). Padahal kenyataannya, MEC server berada di tepi jaringan dengan sumber daya terbatas — terutama saat beban kerja tinggi (intensive workload). Akibatnya:
Jika terlalu banyak user offload sekaligus → kapasitas terlampaui 
Tidak ada mekanisme yang mengatur demand vs supply sumber daya komputasi 
Tidak ada insentif yang adil bagi edge cloud maupun user
Paper ini mengisi gap tersebut dengan mengusulkan mekanisme pricing berbasis Stackelberg game untuk:
Mengontrol jumlah data yang di-offload user agar tidak melebihi kapasitas edge cloud 
Memberikan insentif ekonomi yang rasional bagi edge cloud (maksimalkan revenue) dan user (minimasi latency + biaya) 
Dapat diimplementasikan secara terdistribusi — setiap user memutuskan secara mandiri tanpa koordinasi terpusat

Algorithm 1 — Uniform Pricing (O(log K))

τ ← K,  μ^τ ← 1/F_K   (mulai dari harga tertinggi)
 
REPEAT:
  1. Setiap user hitung ℓ*_k(μ^τ) berdasarkan threshold policy
  2. Edge cloud hitung revenue U_B(μ^τ)
  3. IF Σ ℓ*_k · C_k ≤ F̄  (constraint terpenuhi)
       → turunkan harga: μ^(τ-1) = 1/F_(τ-1), τ ← τ-1
     ELSE
       → set U_B(μ^τ) = 0; BREAK
UNTIL τ ≤ 0
 
OUTPUT: μ* = argmax U_B(μ^τ)
 
Kenapa mulai dari harga tertinggi? Karena semakin tinggi , semakin sedikit user yang offload → total CPU cycles berkurang. Edge cloud menurunkan harga secara bertahap sampai constraint kapasitas aktif (binding), lalu memilih harga yang menghasilkan revenue tertinggi.
Kenapa O(log K)? Karena proses pencarian bisa dilakukan dengan binary search atas kandidat harga — constraint bersifat monoton turun terhadap .
