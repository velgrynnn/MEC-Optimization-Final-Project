1.8
Effect of Increasing the Number of Users
If the total bandwidth B and the cloud computation capacity ¯F remain fixed, increasing
the number of users generally increases the average latency.
This is because the bandwidth per user is
Bk = B
K .
As K increases, Bk decreases. This reduces the uplink and downlink transmission
rates ru
k and rd
k. Consequently, the transmission components of the offloading latency
increase.
Furthermore, more users compete for the same limited cloud computation capacity ¯F.
Therefore, not all users can be selected for offloading. Users that are not selected must
compute locally, and if they have weak local CPU capability, their local latency can be
high.
Therefore, with fixed system resources, the expected trend is

However, because user parameters are randomly generated, the increase in average
latency may not be strictly monotonic in every single simulation run. For example, if
newly added users have small task sizes Rk, low computation intensity Ck, or strong
local CPU frequency Fk, the average latency may not always increase for that particular
realization.
1.9
Summary
The parameters in the numerical setup are sufficient to reproduce the experiment because
they allow the generation of each user’s computation capability Fk, task size Rk, task
intensity Ck, and wireless channel condition hk. These parameters are used to compute
the uplink and downlink transmission rates, the balanced offloading amount mk, the
knapsack weight wk = mkCk, and the knapsack value vk = mkCk/Fk.
The only additional setting required is the number of users K. With the assumption
of equal bandwidth allocation Bk = B/K, the differentiated-pricing problem can then be
solved using a global solver such as SCIP, BARON, or Couenne.
